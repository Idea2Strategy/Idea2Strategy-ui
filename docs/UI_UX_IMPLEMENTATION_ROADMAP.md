# I2S UI/UX 순차 구현 로드맵

## 1. 목적

회의록과 현재 실행형 샘플을 기준으로, 백엔드 구현과 분리해 프론트엔드에서 먼저 설계·검증할 UI/UX 작업을 순차적으로 진행한다.

이 문서의 우선순위는 다음 사용자 흐름을 기준으로 한다.

1. 전략을 잃지 않고 작성한다.
2. 오류를 이해하고 완료한다.
3. 백테스트 결과를 해석한다.
4. 봇의 판단과 주문 상태를 운영한다.
5. 대회 방에서 객관적인 지표를 비교한다.

## 2. 공통 원칙

- 특정 종목, 비중, 기간, 임계값, 주문 가격을 추천하지 않는다.
- 필수 입력은 작성 중 즉시 차단하지 않고 완료 단계에서 모아 검증한다.
- 색상만으로 상태를 구분하지 않고 형태, 명칭, 아이콘과 함께 표시한다.
- 버튼처럼 보이는 요소는 반드시 동작하거나 명확한 비활성 사유를 제공한다.
- 오류 메시지는 `문제 → 영향 → 해결` 순서로 작성한다.
- Basic은 낮은 정보 밀도와 퍼즐 결합 경험을 우선한다.
- Pro는 자유 배치, 타입 포트, 그룹과 재사용을 우선한다.
- 개인 전략, 블루프린트, 주문 기록은 다른 사용자에게 공유하지 않는다.

## 3. 구현 단계

### Phase 1. 전략 편집 신뢰성

상태: 완료

- [x] Basic·Pro 튜토리얼 완료 상태를 모드별로 저장하고 자동 재실행을 방지한다.
- [x] 완료와 전체 건너뛰기를 모두 확인 완료로 처리하고 수동 다시 보기를 제공한다.
- [x] 연결부를 다섯 도형군과 1:1 크기로 단순화한다.
- [x] 라이브러리, Basic 퍼즐과 Pro 캔버스가 같은 포트 컴포넌트를 사용한다.
- [x] Pro 연결을 드래그하는 동안 연결 가능한 포트를 강조한다.
- [x] Pro 연결을 드래그하는 동안 연결할 수 없는 노드 전체를 어둡게 표시한다.
- [x] 연결 시작 노드, 연결 가능 노드, 연결 불가 노드를 서로 다른 상태로 표시한다.
- [x] Basic과 Pro의 실제 오류·경고 수를 완료 검사창에 연결한다.
- [x] 오류가 남아 있으면 봇 생성 이동 대신 첫 문제 위치로 안내한다.
- [x] 실제 저장이 아닌 상태를 `자동 저장됨`으로 표현하지 않는다.
- [x] 전략 이름과 편집 내용 저장 상태를 하나의 공통 상태 모델로 통합한다.
- [x] 접힌 그룹의 외부 연결을 방향·타입·시간축별 대표 포트로 이어 표시한다.
- [x] 대표 포트에 연결 수와 내부 연결 목록을 제공한다.
- [x] 선택 노드의 `Delete`·`Backspace` 삭제와 실행 취소를 제공한다.
- [x] 드래그 중에만 나타나는 중앙 하단 삭제 박스에서 즉시 드롭 삭제를 제공한다.
- [x] 삭제 박스 아래 하단 가장자리를 자동 화면 이동 영역으로 분리한다.

완료 기준:

- 사용자가 연결선을 잡는 즉시 후보 노드를 한눈에 구분할 수 있다.
- 연결할 수 없는 노드는 포트뿐 아니라 카드 전체가 흐려진다.
- 완료 검사창의 오류 수가 현재 편집기와 일치한다.
- 오류가 있는 상태에서 봇 생성 화면으로 진행할 수 없다.
- 그룹을 접어도 그룹 안팎의 연결 관계를 확인할 수 있다.
- 노드를 빠르게 삭제하되 준비 전 드롭과 왼쪽 화면 이동은 오삭제로 이어지지 않는다.

### Phase 2. 전략 보관과 전환

상태: 완료

- [x] 내 전략 목록, 최근 편집, 새 전략, 복제, 삭제
- [x] 전략 보관과 보관 해제
- [x] 저장 중, 저장 완료, 저장 실패 상태
- [x] 저장 실패 재시도 동작
- [x] 마지막 편집 전략 이어하기
- [x] 전략 버전과 버전별 변경 요약
- [x] Basic에서 Pro로 전환하기 전 변환 미리보기와 초안 변환
- [x] Pro 원본을 보존하고 Basic으로 축소 변환하지 않는다는 안내
- [x] 블루프린트 이름 변경, 삭제, 검색, 미리보기
- [x] 초기화 전 변경 내용 손실 확인
- [x] 현재 샘플의 저장 범위가 이 브라우저에 한정됨을 명시

완료 기준:

- 새로고침 또는 화면 이동 이후에도 사용자가 작업 위치를 이해할 수 있다.
- 모드 전환 전에 유지되는 요소와 사라지는 요소를 확인할 수 있다.
- 전략 삭제와 초기화는 실수로 실행되지 않는다.

### Phase 3. 봇 생성과 백테스트

상태: 완료

- [x] 봇 생성 최종 확인 단계
- [x] 전략 버전, 초기 가상자금, 운영 일정, 주문 정책 확인
- [x] 공식 비교 구간과 사용자 지정 구간 분리
- [x] 수수료·슬리피지·벤치마크·시장 시간 입력
- [x] 백테스트 준비, 대기, 실행, 완료, 실패, 취소 상태
- [x] 과거 백테스트 목록과 결과 재열람
- [x] 학습·검증 구간 비교
- [x] 누적 수익률, 최대 낙폭, 변동성, 샤프지수, 승률, 거래 횟수
- [x] 기업행사·배당·공매도·결측 데이터 적용 범위
- [x] 결과 지표별 초보자용 설명

완료 기준:

- 실행 전 사용자가 어떤 조건으로 테스트하는지 한 화면에서 확인한다.
- 진행 상태를 닫았다가 다시 열어도 현재 단계와 다음 행동을 이해한다.
- 결과와 데이터 한계를 같은 화면에서 확인한다.

### Phase 4. 봇 운영

상태: 완료

- [x] 봇 상태별 목록과 빈 화면
- [x] 주문·부분 체결·체결·취소 상태
- [x] 포지션, 평균 단가, 현금, 평가손익
- [x] 가격 차트와 주문·체결 시점
- [x] 주문하지 않은 판단의 조건별 근거
- [x] 활동 기록 검색과 필터
- [x] 통신 단절·재연결·중단 타임라인
- [x] 일시정지·중단·재개 전 영향 요약
- [x] 봇 이름·일정·알림 설정
- [x] 운영 종료와 영구 삭제 분리
- [x] 삭제 시 봇 이름 재입력
- [x] 전략 버전과 봇 식별값

완료 기준:

- 문제 발생 시 성과보다 원인과 조치가 먼저 보인다.
- 사용자가 주문이 유지되는지 취소되는지 실행 전에 이해한다.
- 사용자 행동과 시스템 사건을 구분해 추적할 수 있다.

### Phase 5. 대회 방

상태: 완료

- [x] 참여할 봇과 전략 버전 선택
- [x] 제출 가능·불가능 봇과 이유 표시
- [x] 참여, 철회, 모집 중 봇 교체
- [x] 시작 후 전략 변경 제한 안내
- [x] 시작 자본, 종목 범위, 벤치마크, 체결·비용 기준
- [x] 수익률, MDD, 변동성, 샤프지수, 승률, 거래 횟수별 비교
- [x] 사용자가 선택한 지표로 정렬
- [x] 내 봇 위치 강조
- [x] 참가자와 제출 현황 관리
- [x] 모집 중단, 일정 변경, 대회 종료와 운영 이력
- [x] 공식 방과 개인 방의 권한 차이

완료 기준:

- [x] 전략을 공개하지 않고도 객관적인 성과 지표를 비교할 수 있다.
- [x] 단일 추천 순위 대신 사용자가 원하는 지표를 선택한다.
- [x] 방 운영자가 변경의 영향과 참가자 상태를 확인한다.

### Phase 6. 공통 신뢰성과 접근성

상태: 진행 중

- [x] 알림 읽음 상태, 심각도, 유형 필터와 관련 화면 이동 (`/notifications`)
- [x] 알림 설정 (내 계정 · 조치·대회·이메일 항목별 선택)
- [x] KST·ET·서머타임 설명과 시간대 표기 선택
- [x] 데이터 기준 시각과 샘플 데이터 표기 (`SampleDataNote`)
- [x] 화면별 도움말과 금융 용어집 검색 (`/help`)
- [x] 모의투자·데이터 한계 확인 (도움말 · 이 시험판의 한계)
- [x] 성공, 오류, 빈 결과, 로딩 상태 통일 (`EmptyState`·`ErrorState`·`LoadingState`)
- [x] 키보드 탐색, 포커스, 스크린리더 명칭
- [x] 색상 이외의 상태 표현 (심각도별 아이콘과 명칭 병기)
- [x] 작은 화면 읽기 전용 모드 유지
- [x] 모션 줄이기 설정 준수 (OS 설정과 내 계정의 명시적 선택)
- [ ] 실시간 시장 상태 표시. 사용자가 이 화면에서 조치할 수 있는 정보가 아니라고 판단해 현재 제품 화면에서 제외했다.
- [ ] 데이터 공급자별 지연·결측 상태. 실제 데이터 연동 이후로 미룬다.

미구현으로 남긴 두 항목은 실제 시장 데이터 연동 전에는 임의 값을 만들어야 하므로, 데이터를 생성하지 않는다는 원칙에 따라 보류했다.

완료 기준:

- 마우스와 색상에만 의존하지 않고 주요 기능을 사용할 수 있다.
- 사용자는 데이터가 언제, 어디에서 왔고 어떤 제한이 있는지 확인한다.
- 모든 비동기 작업에 로딩·성공·오류·재시도 상태가 존재한다.

## 4. 구현 순서

다음 작업은 Phase 1 완료 후 아래 순서로 진행한다.

1. 내 전략 목록과 저장 상태
2. Basic/Pro 전환 미리보기
3. 봇 생성 최종 확인
4. 백테스트 진행·결과·기록
5. 주문·포지션·판단 로그
6. 대회 성과 비교
7. 알림·도움말·접근성

각 단계는 `기본 상태`, `로딩 상태`, `빈 상태`, `오류 상태`, `완료 상태`를 함께 구현한 뒤 다음 단계로 이동한다.
